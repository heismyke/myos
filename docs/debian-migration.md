# ZumaOS: AlmaLinux → Debian migration and desktop plan

Status: analysis complete, milestone 1 (dev environment + design system +
Quick Settings) in progress. Written 2026-10-29.

## 1. Audit of the current (AlmaLinux) implementation

### What ZumaOS is today

ZumaOS is **not** a traditional RPM distribution. It is a **bootc / OSTree
container image** layered on `quay.io/almalinuxorg/atomic-desktop-kde`
(AlmaLinux 10, KDE Plasma 6), built from one `Containerfile`:

| Stage | Base | Does |
| --- | --- | --- |
| `assets` | `fedora:43` | Renders `branding/` with `rsvg-convert` + Pillow; fetches the Inter font (pinned, checksummed). |
| `appgrid` | AlmaLinux Atomic KDE | Builds the AppGrid launcher applet from a pinned, checksummed tarball (`-devel` RPMs from CRB). |
| final | AlmaLinux Atomic KDE | `dnf install` Papirus + JetBrains Mono (EPEL), copies `assets`, `appgrid` and `files/` over `/`, then patches upstream files with `sed`/`ln`. |

- **Packaging:** there are no RPM spec files. Everything is image layering.
  Nothing needs RPM → deb conversion; the work is turning layers into
  Debian packages.
- **Desktop:** KDE Plasma 6 with a global theme (`org.zumaos.desktop`), the
  `ZumaOS` colour scheme, an Aurorae window decoration generated by
  `branding/aurorae/make-theme.py`, and AppGrid as the Start menu.
- **Display manager:** Plasma Login Manager (commit `7c22b00` moved away from
  SDDM). It is not in Debian 13.
- **ISO / CI:** `AlmaLinux/atomic-ci` reusable workflows build and sign the
  image and, on manual dispatch, an Anaconda ISO. `iso-hook.sh` writes the
  Anaconda `.buildstamp`.
- **Updates:** image-based (bootc), atomic with rollback.
- **Kernel:** stock AlmaLinux kernel, no custom config or out-of-tree drivers.
  The only kernel-adjacent step is the `dracut --add ostree` initramfs rebuild
  for Plymouth.

### Reusable as-is (distro-neutral)

- `branding/`: logo, glyph, wordmark, wallpapers, Plymouth parts, Settings icon,
  `render.sh` (only its tool dependencies change).
- `branding/aurorae/make-theme.py` (pure Python output).
- `files/etc/xdg/*`: `kdeglobals`, `kwinrc`, `krunnerrc`, `kscreenlockerrc`,
  `ksplashrc`. KDE config is identical on Debian.
- `files/usr/share/color-schemes/ZumaOS.colors`.
- `files/usr/share/plasma/look-and-feel/org.zumaos.desktop/` (the layout script
  will change to follow the Figma shelf).
- `files/usr/share/plymouth/themes/zumaos/` and `files/etc/plymouth/`.
- `files/etc/skel/Desktop/trash.desktop`.

### Must be rewritten

- `Containerfile`, `iso-hook.sh`, the CI workflow (items 1–12 above).
- Every `sed` against upstream files (items 7, 10) → package-owned overrides.
- Display manager theme: there is none today (PLM used the stock greeter with
  a wallpaper); an SDDM Qt 6 theme must be written.

## 2. Findings that need a decision

1. **The Figma file is not a Windows 11 design.** `JOS 4.x Concept (BETA)
   (Community)` is a ChromeOS-style concept: a full-width 56px "shelf" with a
   launcher button on the left and status pills on the right, Material Symbols
   iconography, neutral greys (`#2D2D2D` / `#9A9A9A` / `#7B7B7B`), Manrope, and
   a purple wave wallpaper. The repo's current look is Windows 11 (centred
   taskbar, Start menu, zumaos.com violet `#A855F7`, Inter). The brief says the
   Figma file is the source of truth, so this plan follows it, but the
   "Windows 11-like" goal and the design disagree.
2. **It's a Figma Community file branded "JOS".** Community files are published
   under CC BY 4.0, which allows reuse with attribution, but the JOS name and
   logo must not ship, and the wallpaper's origin should be confirmed before
   distributing it.
3. **Design gaps.** No hover/pressed/focus states, no motion specs, no light
   variant of Quick Settings, no frames for Quick Settings pages 2–3, no tile
   editor. Typos in the file ("Acessibility", "System uptate is avalible") are
   corrected in code. Where something is missing the implementation picks the
   most neutral option and says so in a comment; a designer should confirm.
4. **Frames not yet reviewed in detail:** login/lock, Settings (one
   Personalization frame exists on the Assets page), file manager, window
   decoration. Their node URLs are needed before those components start.

## 3. Debian migration architecture

### Release

**Debian 13 "trixie"** (stable since August 2025; Plasma 6.3.6, Qt 6.8.2,
KF 6.13, kernel 6.12 LTS; security support until 2028, LTS to 2030). Track
`trixie-backports` for newer kernels/Mesa only when hardware needs them.
Plasma stays on the stable 6.3 series; Plasma upgrades arrive with Debian 14.

### Shape of the system

A conventional, apt-managed Debian system plus a small set of ZumaOS packages
served from a ZumaOS apt repository. No in-place conversion of AlmaLinux
installs: users reinstall from the new ISO (home directories can be carried
over; KDE config is compatible).

```
Debian 13 main + contrib + non-free-firmware  (unmodified)
        │
        ├── zumaos-archive-keyring      repo key + deb822 sources file
        ├── zumaos-release              os-release/issue via dpkg-divert, ID_LIKE=debian
        ├── zumaos-branding             logos, wallpapers, Plymouth theme, icons
        ├── zumaos-design               QML design system: org.zumaos.style + icons
        ├── zumaos-desktop-settings     /etc/xdg defaults, look-and-feel, colour scheme,
        │                               Aurorae theme, XDG_DATA_DIRS overrides
        ├── plasma-applet-zumaos-*      Quick Settings, shelf pills, launcher, …
        ├── sddm-theme-zumaos           login screen (Qt 6 QML)
        ├── calamares-settings-zumaos   installer branding and module config
        └── zumaos-desktop              metapackage pulling it all + Plasma
```

### Package management and overrides

- Each package lives in `packages/<name>/` with a `debian/` directory, built
  with `dpkg-buildpackage` in a clean chroot (`sbuild`) in CI.
- Publish to a signed apt repo (`reprepro` or `aptly`) on GitHub Pages or an
  object store. `zumaos-archive-keyring` installs the key and
  `/etc/apt/sources.list.d/zumaos.sources`.
- **No edits to files owned by other packages.** Renaming Settings and its
  categories becomes override copies in `/usr/share/zumaos/xdg/` placed first
  in `XDG_DATA_DIRS` via `/etc/environment.d/`. `os-release` uses
  `dpkg-divert`. KDE defaults stay in `/etc/xdg` as conffiles, so user
  changes and upgrades are handled by dpkg's conffile logic.

### Services and security

| AlmaLinux image | Debian 13 |
| --- | --- |
| SELinux enforcing | AppArmor (Debian default), profiles from `apparmor-profiles` |
| firewalld | firewalld (keeps `plasma-firewall` UI working) |
| bootc atomic updates + rollback | apt + `unattended-upgrades` for security, Discover/PackageKit for the UI. **Loses atomic rollback**: mitigate later with btrfs + snapper snapshots on upgrade |
| Plasma Login Manager | SDDM (`sddm`, Qt 6 greeter) |
| dracut | initramfs-tools |
| NetworkManager, BlueZ, PipeWire, UPower, power-profiles-daemon | same services, Debian packages |

### Kernel and drivers

Debian's `linux-image-amd64` (6.12) plus `firmware-linux-nonfree`,
`firmware-iwlwifi`, `firmware-realtek`, `firmware-amd-graphics` from
`non-free-firmware`, and `intel-microcode` / `amd64-microcode`. No custom
kernel was used before, so nothing to port.

### ISO build

**live-build** (what Debian's own live images use) driven by a checked-in
`iso/` config: package lists, hooks, `includes.chroot`, the ZumaOS apt repo,
and **Calamares** as the installer (`calamares-settings-zumaos` for branding,
partitioning defaults and the slideshow). Reproducibility: pin
`snapshot.debian.org` timestamps for release builds, record package manifests,
build in a Debian container in CI. Boot splash = Plymouth; GRUB theme from
`zumaos-branding`.

### Testing

- QML: `qmltestrunner` component tests and the screenshot preview
  (`dev/run-preview.sh`) compared against Figma exports.
- Packages: `lintian`, `piuparts` (install/upgrade/remove in a clean chroot).
- ISO: boot in QEMU/KVM (OVMF + BIOS) with `openQA`-style scripted checks:
  install via Calamares, reboot, log in through SDDM, network up, audio sink
  present, Bluetooth service running, Discover sees updates.

## 4. KDE Plasma 6 customisation strategy

Prefer, in order: configuration → themes → Plasma applets / KWin scripts →
new apps. Fork nothing.

| Component | Approach |
| --- | --- |
| Design system | `zumaos-design`: `org.zumaos.style` QML module (tokens singleton + controls) and `tokens.json` extracted from Figma. Every ZumaOS QML surface imports it. |
| Shelf (taskbar) | Plasma panel (bottom, 56px, floating off) laid out by the look-and-feel script, with ZumaOS applets for the pill groups (date, clock, tray, Quick Settings trigger). The stock Task Manager stays for running apps. |
| Launcher | The Figma file has its own launcher (popup grid + full-screen "App di Sistema" view). Build it as a ZumaOS applet on Plasma's Kicker/KRunner models instead of patching AppGrid; retire AppGrid. |
| Quick Settings / notifications | ZumaOS applets. Backends are Plasma's own QML APIs (plasma-nm, BlueZ-Qt, plasma-pa, notification manager, session management) and D-Bus for PowerDevil/power profiles. |
| Popup chrome | A `ZumaOS` Plasma desktop theme (SVG) with transparent dialog backgrounds so applets draw their own Figma cards. |
| Window decorations | Keep generated Aurorae theme, regenerate from Figma tokens once the window frame (Terminal/Settings frames on the Assets page) is extracted. Rounded corners/shadows via KWin's built-in shadow + a KWin effect only if needed. |
| Login / lock | `sddm-theme-zumaos` (Qt 6) and the lock screen QML inside `org.zumaos.desktop`. Both authenticate through PAM via SDDM / kscreenlocker; no custom auth. |
| File explorer | Dolphin, customised: ZumaOS icon theme (folder icons from the Figma Assets page), Places defaults, view settings in `/etc/xdg/dolphinrc`, service menus. A new file manager is not justified. |
| Settings | A ZumaOS Kirigami shell that hosts the existing KCMs (KCMUtils), with Windows 11-style categories from the Figma Settings frame. Real backends come from the KCMs; no static mock pages. Replace individual KCM UIs only where the design demands it. |
| Window management | KWin config (`kwinrc`), built-in snapping/tiling, virtual desktops, Overview; KWin scripts for anything extra. |

Found while implementing:

- Figma exports wrap every icon in a full-canvas `mask-type:alpha` mask. QtSvg
  applies it as a luminance mask (icons at ~85% opacity).
  `packages/zumaos-design/tools/import-figma-icons.py` strips it; run it on
  every future icon export.
- QML can't have properties named `on` + capital letter, so the Figma-style
  `onSurface` token is `content` in code.
- `BatteryControlModel` is in `org.kde.plasma.private.battery`, not
  `…batterymonitor`, on Plasma 6.3. The private Plasma imports are all kept in
  `PlasmaBackend.qml` for this reason.

Open design questions (implemented provisionally, marked in code):

- Page indicator: the design shows three dots but only one page of tiles
  exists. The indicator shows the real page count (one).
- Hover/pressed/focus states: none in Figma. Material state layers (8%/12%)
  and a 2px focus ring are used.
- Mic Access tile uses the darker `#7B7B7B` in the design while saying
  "Available"; its meaning (muted? privacy state?) needs a decision.
- Chevron-down button: no destination in the design; it closes the panel.
- Pencil button: there is no tile-editor design; it opens the applet's
  configuration page with tile checkboxes.
- The notification strip is hidden when there are no notifications.
- In a panel the popup still gets Plasma's dialog frame around the cards
  until the ZumaOS Plasma theme (M4) makes it transparent.
